## 程序为什么会「炸」

```python
print(10 / 0)
print('程序执行完成')
```

输出

```python
Traceback (most recent call last):
  File "/Users/along/Desktop/Agent-web/python-code/14.异常处理.py", line 1, in <module>
    print(10 / 0)
          ~~~^~~
ZeroDivisionError: division by zero
```

这就叫「异常」。Python 在执行 `10 / 0` 的时候发现：除数是零，这事儿数学上没法干，于是它创建了一个 `ZeroDivisionError` 对象，把这个对象「抛」出来。如果没人接，这个异常就会一路冒泡到最外层，最后由 Python 解释器接住，打印 traceback，然后退出程序。

在看一个案例：
```python
nums = [1, 2, 3]
print(nums[10])

IndexError: list index out of range
```

`IndexError`，下标越界


## 最朴素的 try / except

```python
try:
    result = 10 / 0
    print(result)
except ZeroDivisionError:
    print('哎呀，除数不能是零')

print('程序继续运行')
```

输出结果

```python
哎呀，除数不能是零
程序继续运行
```

是不是发现，红字 traceback 没了，程序也没崩，最后那句「程序继续运行」也乖乖打印出来了。

- `try / except` 的语法就这么简单，记住三件事：
    - `try`: 块里放「可能出问题」的代码
    - `except XxxError`: 块里放「出了问题该怎么办」的代码
    - 如果 `try` 块没出错，`except` 块完全跳过，跟没写一样

## 一次捕获多种异常

```python
def parse_age(s):
    try:
        age = int(s)
        return 100 / age
    except ZeroDivisionError:
        return '年龄不能是 0'
    except ValueError:
        return '输入的不是数字'


print(parse_age('25'))
print(parse_age('0'))
print(parse_age('abc'))
```
输出
```python
4.0
年龄不能是 0
输入的不是数字
```

这里使用多个except分支捕获异常，也可以用更简洁的方式：

```python
def parse_age(s):
    try:
        age = int(s)
        return 100 / age
    except (ZeroDivisionError, ValueError):
        return '输入有问题'


print(parse_age('25'))
print(parse_age('0'))
print(parse_age('abc'))
```
输出
```python
4.0
输入有问题
输入有问题
```

## 拿到异常对象—— `as e`
各位光知道「出错了」还不够，有时候你需要知道「具体错在哪儿」。Python 允许你用 as 把异常对象抓出来：

```python
def parse_age(s):
    try:
        age = int(s)
        return 100 / age
    except (ZeroDivisionError, ValueError) as e:
        return f'出错啦：{type(e).__name__} - {e}'


print(parse_age('0'))
print(parse_age('abc'))
```

输出：

```python
出错啦：ZeroDivisionError - division by zero
出错啦：ValueError - invalid literal for int() with base 10: 'abc'
```

e 就是异常对象本身。type(e).__name__ 是它的类名，str(e) 是它的错误信息。在做日志、做调试的时候，这种写法比简单打印「出错啦」要有用得多。

## 万能兜底—— `except Exception`

有时候，各位不知道代码里到底会抛什么异常，又不想写一长串 except。这时候可以用一个「父类」来兜底：

```python
try:
    risky_operation()
except Exception as e:
    print(f'未知错误：{e}')
```

`Exception` 是绝大多数异常的「祖宗」，写它就等于「能接住几乎所有异常」。

但是！这里有个坑：很多新手喜欢写 `except`: 后面什么类型都不写，或者写 `except BaseException:`。这两种写法都太狠了——它们会把 `KeyboardInterrupt`（你按 `Ctrl+C` 想中断程序）和 `SystemExit`（程序主动 `sys.exit()`）也接住，导致你的程序按 `Ctrl+C` 都停不下来。

记住：兜底用 `Exception`，不要用 `BaseException`，更不要写裸 `except:`。这是江湖规矩。


## 异常的家族——继承层级

各位可能要问：「Exception 是几乎所有异常的祖宗，那它上面还有谁？下面又有哪些？」

```python
BaseException
 ├── SystemExit
 ├── KeyboardInterrupt
 ├── GeneratorExit
 └── Exception
      ├── ArithmeticError
      │    ├── ZeroDivisionError
      │    └── OverflowError
      ├── LookupError
      │    ├── IndexError
      │    └── KeyError
      ├── ValueError
      ├── TypeError
      ├── AttributeError
      ├── NameError
      ├── OSError
      │    └── FileNotFoundError
      └── ...
```

- 这棵树读起来要点有几个：
    - 最顶层是 `BaseException`，所有异常都继承自它
    - `SystemExit` / `KeyboardInterrupt` / `GeneratorExit` 这三个跟「程序流程控制」相关，不应该被普通的 `try/except` 接住
    - 其他业务相关的异常都在 `Exception` 下面
    - `Exception` 又分成几个大家族：算术错误、查找错误、值错误、类型错误等等

## `else`——没出错的时候才走

try / except 还有两个好搭档：else 和 finally。我们先看 else。

```python
def divide(a, b):
    try:
        result = a / b
    except ZeroDivisionError:
        print('除数不能是零')
    else:
        print(f'计算成功，结果是 {result}')


divide(10, 2) # 计算成功，结果是 5.0
divide(10, 0) # 除数不能是零
```
> `else` 块只在 `try` 块没有抛异常的时候执行

## finally——不管啥情况都得跑

`finally` 块更狠：不管 `try` 块成功还是失败，不管异常被接住还是没被接住，`finally` 一定会执行。

```python
def read_first_line(path):
    f = open(path, 'r')
    try:
        return f.readline()
    finally:
        f.close()
        print(f'已关闭 {path}')
```


## 主动抛异常——raise

```python
def set_age(age):
    if age < 0:
        raise ValueError(f'年龄不能是负数，你传了 {age}')
    if age > 200:
        raise ValueError(f'年龄不能超过 200，你传了 {age}')
    return age


try:
    set_age(-5)
except ValueError as e:
    print(f'参数有问题：{e}') # 参数有问题：年龄不能是负数，你传了 -5
```

## 内置异常速查表

| 异常类 | 触发场景 | 例子 |
| --- | --- | --- |
| `ValueError` | 参数类型合适，但值不合法 | `int('abc')` |
| `TypeError` | 操作或函数接收了不支持的类型 | `'a' + 1` |
| `KeyError` | 访问字典中不存在的键 | `{'a': 1}['b']` |
| `IndexError` | 序列索引越界 | `[1, 2][5]` |
| `AttributeError` | 访问对象不存在的属性或方法 | `'abc'.foo` |
| `NameError` | 使用当前作用域中找不到的名称 | `print(undefined_x)` |
| `FileNotFoundError` | 访问不存在的文件或目录，是 `OSError` 的子类 | `open('not_exist.txt')` |
| `ZeroDivisionError` | 除法、整除或取余运算的除数为零 | `1 / 0` |
| `ImportError` | 导入模块或模块中的名称失败 | `from math import not_exist_name` |
| `ModuleNotFoundError` | 导入时找不到模块，是 `ImportError` 的子类 | `import not_exist_module` |
| `RuntimeError` | 检测到不适合归入其他异常类别的运行时错误 | `raise RuntimeError('当前状态不允许此操作')` |
| `NotImplementedError` | 需要子类实现的方法尚未提供具体实现 | `raise NotImplementedError('子类需要实现此方法')` |
| `StopIteration` | 迭代器已没有可返回的元素 | `next(iter([]))` |
| `OSError` | 文件操作、系统调用等发生操作系统相关错误 | 文件读写失败、磁盘空间不足等 |
| `PermissionError` | 操作权限不足，是 `OSError` 的子类 | 无权限时尝试打开受保护文件 |
| `RecursionError` | 超过解释器允许的最大递归深度，是 `RuntimeError` 的子类 | 缺少终止条件的递归不断调用自身 |
| `KeyboardInterrupt` | 用户请求中断程序，通常由按下 Ctrl+C 触发 | 运行程序时按 Ctrl+C |
| `SystemExit` | 程序请求退出 | `sys.exit()` |
