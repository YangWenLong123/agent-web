# 工具介绍

| 工具        | 主要作用             | 解决的问题                             |
| ----------- | -------------------- | -------------------------------------- |
| `venv`      | 创建虚拟环境         | 不同项目之间的依赖互相污染             |
| `pip`       | 安装和管理 Python 包 | 如何安装 `fastapi`、`pytest` 等依赖    |
| `pip-tools` | 管理和锁定依赖版本   | 如何让团队和部署环境安装完全一致的版本 |

# 1. `venv：创建隔离的 Python 环境

`venv` 是 Python 自带的虚拟环境工具。
例如，项目 A 需要 `requests 2.x，项目 B 需要另一个版本。如果都安装到系统 Python 中，就容易发生冲突。`venv` 可以为每个项目创建独立环境。

```sh
python -m venv .venv
```

激活环境：

```sh
# macOS / Linux
source .venv/bin/activate

# Windows PowerShell
.venv\Scripts\Activate.ps1
```

激活后安装的包只属于当前项目：

```sh
python -m pip install fastapi
```

退出环境：

```sh
deactivate
```

`.venv` 通常应该加入 `.gitignore`，不要提交到 `Git`。

# 2. pip：安装 Python 包

`pip` 是 `Python` 最常用的包安装工具，类似前端里的 `npm` 或 `pnpm`。

安装包：

```sh
python -m pip install fastapi
python -m pip install pytest
```

安装指定版本：

```sh
python -m pip install "fastapi==0.115.0"
```

查看已安装的包：

```sh
python -m pip list
```

卸载包：

```sh
python -m pip uninstall fastapi
```

导出当前环境中的包：

```sh
python -m pip freeze > requirements.txt
```

这里推荐使用：

```sh
python -m pip
```

而不是直接使用：

```sh
pip
```

因为 `python -m pip` 能明确表示“使用当前这个 Python 环境里的 pip”，不容易装错环境。

# 3. pip-tools：整理和锁定依赖

`pip-tools` 不是 Python 内置工具，需要单独安装：

```sh
python -m pip install pip-tools
```

它主要提供两个命令：

- pip-compile
- pip-sync

`pip-compile`：生成锁定版本

创建一个 `requirements.in` 文件，只写你直接需要的依赖：

```sh
fastapi
httpx
pytest
```

然后执行：

```sh
pip-compile requirements.in
```

它会生成 `requirements.txt`，里面包含精确版本和间接依赖，例如：

```sh
fastapi==0.115.0
httpx==0.27.2
pydantic==2.9.2
starlette==0.38.6
```

这样开发环境、测试环境和生产环境就可以使用同一组版本。

`pip-sync`：让环境严格匹配锁定文件

```sh
pip-sync requirements.txt
```

它会：

- 安装 requirements.txt 中缺少的包
- 调整版本
- 删除环境中多余的包

因此使用时要小心，它可能会卸载当前环境里没有写入 `requirements.txt` 的包。

# 三者配合使用

传统项目通常这样初始化：

```sh
mkdir agent-python-lab
cd agent-python-lab

python -m venv .venv
source .venv/bin/activate

python -m pip install --upgrade pip pip-tools
```

创建 `requirements.in`：

```sh
fastapi
httpx
pytest
ruff
```

生成锁定依赖：

```sh
pip-compile requirements.in
```

安装精确依赖：

```sh
pip-sync requirements.txt
```

之后的关系是：

```sh
venv       创建隔离环境
   ↓
pip        安装 Python 包
   ↓
pip-tools  生成并同步精确的依赖版本
```

# 和 `uv` 的关系

`uv` 可以把这几个工具的常见工作集中起来：

```sh
uv venv                 # 类似 venv
uv add fastapi pytest   # 类似 pip install，并记录项目依赖
uv lock                 # 锁定依赖版本
uv sync                 # 同步项目环境
uv run pytest           # 在项目环境中执行命令
```

所以：

- 想理解 Python 传统工具链：学习 venv + pip + pip-tools
- 想快速开始新项目：使用 uv
- 两者不需要同时使用，选一套即可
