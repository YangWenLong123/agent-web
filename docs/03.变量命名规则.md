# Python 变量命名规则与常见命名方式

变量名是代码中用于标识数据的名称。好的命名应当让读者不查看具体实现，也能大致理解数据的含义、类型和用途。

Python 的命名通常遵循两类约定：

- **语法规则**：不符合规则的名称会导致代码无法运行。
- **编码规范**：符合 Python 社区习惯的命名方式，可以提高代码可读性和一致性。

> Python 变量名区分大小写，例如 `name`、`Name` 和 `NAME` 是三个不同的名称。但除非表达不同含义，不建议仅通过大小写区分名称。

## 一、变量名的语法规则

### 1. 只能包含指定字符

变量名只能由以下字符组成：

- 英文字母：`a-z`、`A-Z`
- 数字：`0-9`
- 下划线：`_`
- 在 Python 3 中，也可以使用部分 Unicode 字符，但实际项目通常推荐使用英文命名

```python
user_name = "Alice"
item_count = 3
_total = 100
```

以下名称包含不允许的字符：

```python
user-name = "Alice"      # 错误：不能使用连字符
user name = "Alice"      # 错误：不能包含空格
user.name = "Alice"      # 错误：点号用于访问属性
```

### 2. 不能以数字开头

变量名可以包含数字，但第一个字符不能是数字。

```python
name1 = "Alice"          # 正确
version_2 = "2.0"        # 正确

1st_name = "Alice"       # 错误：以数字开头
2026_total = 100         # 错误：以数字开头
```

如果需要表达顺序，推荐将数字放在名称末尾，或用更有意义的词表达：

```python
user1 = "Alice"
user2 = "Bob"
first_user = "Alice"
second_user = "Bob"
```

### 3. 不能使用 Python 关键字

关键字是 Python 语言保留的特殊单词，不能直接作为变量名。

常见关键字包括：

```text
False   None    True    and     as      assert
async   await   break   case    class   continue
def     del     elif    else    except  finally
for     from    global  if      import  in
is      lambda  match   nonlocal not     or
pass    raise   return  try     while   with
yield
```

```python
class = "A"                 # 错误：class 是关键字
for = 10                     # 错误：for 是关键字
```

如果某个业务字段恰好与关键字重名，可以在名称末尾添加下划线：

```python
class_ = "A"
from_ = "internal"
```

可以使用 `keyword` 模块检查一个单词是否为关键字：

```python
import keyword

print(keyword.iskeyword("class"))  # True
print(keyword.iskeyword("name"))   # False
```

### 4. 不能使用内置名称作为普通变量名

Python 内置函数和类型虽然不是关键字，但不建议被覆盖，否则会影响后续代码的正常使用。

```python
list = [1, 2, 3]       # 不推荐：覆盖内置类型 list
str = "hello"          # 不推荐：覆盖内置类型 str
sum = 100              # 不推荐：覆盖内置函数 sum
id = "user-001"        # 不推荐：覆盖内置函数 id
```

例如，覆盖 `list` 后，下面的代码会报错：

```python
list = [1, 2, 3]
values = list((4, 5))  # TypeError：list 已经不再是内置类型
```

推荐使用具有实际含义的名称：

```python
user_list = [1, 2, 3]
total_sum = 100
user_id = "user-001"
```

可使用 `dir(builtins)` 查看常见内置名称：

```python
import builtins

print("list" in dir(builtins))  # True
```

### 5. 变量名不能包含运算符和标点符号

空格、连字符、点号等字符在 Python 中具有其他语法含义，不能用于普通变量名。

```python
first-name = "Alice"    # 被解析为减法表达式
user.name = "Alice"     # 被解析为属性赋值
price$ = 10              # 错误：不能使用 $
```

在需要分隔单词时，应使用下划线：

```python
first_name = "Alice"
user_name = "Alice"
```

## 二、Python 推荐的命名风格

Python 官方风格指南 PEP 8 对命名有明确建议。最常用的风格如下：

| 对象           | 推荐风格                        | 示例                |
| -------------- | ------------------------------- | ------------------- |
| 普通变量       | `snake_case`，小写加下划线      | `user_name`         |
| 函数和方法     | `snake_case`                    | `calculate_total()` |
| 常量           | `UPPER_SNAKE_CASE`              | `MAX_RETRY_COUNT`   |
| 类             | `CapWords` / `PascalCase`       | `UserProfile`       |
| 异常类         | `CapWords`，通常以 `Error` 结尾 | `ValidationError`   |
| 模块           | 短小的 `snake_case`             | `user_service.py`   |
| 包             | 短小的小写名称                  | `utils`             |
| 受保护成员     | 单个前导下划线                  | `_cache`            |
| 强提示私有成员 | 两个前导下划线                  | `__token`           |
| 特殊方法       | 两端两个下划线                  | `__init__`          |

## 三、普通变量的常见命名方式

### 1. 使用 `snake_case`

多个单词组成的变量名使用小写字母，并用下划线分隔。这是 Python 中最常见、最推荐的变量命名方式。

```python
user_name = "Alice"
email_address = "alice@example.com"
order_total_amount = 199.99
is_authenticated = True
```

不推荐使用驼峰式或全部连写：

```python
userName = "Alice"          # Python 中不推荐
emailaddress = "..."        # 可读性较差
user-name = "Alice"         # 语法错误
```

### 2. 名称应表达实际含义

变量名应说明数据是什么，而不是只说明它是一个值。

```python
# 不推荐
x = 18
y = "Alice"
data = ["Python", "SQL"]

# 推荐
user_age = 18
user_name = "Alice"
course_names = ["Python", "SQL"]
```

### 3. 避免过度缩写

缩写只有在团队成员普遍理解时才适合使用。常见且明确的缩写可以保留，例如 `id`、`url`、`http`、`api`。

```python
# 不推荐
usr_nm = "Alice"
addr = "..."              # 如果上下文不明确，含义可能不清楚
proc_tm = 10

# 推荐
user_name = "Alice"
address = "..."
processing_time = 10
```

对于常见技术缩写，Python 风格通常仍然使用小写：

```python
user_id = 1001
api_url = "https://example.com"
http_status_code = 200
json_data = {"name": "Alice"}
```

### 4. 变量名长度要适中

名称太短，无法表达含义；名称过长，则会降低阅读效率。应根据作用域和使用频率调整长度：

```python
# 简短循环的局部变量可以适当简洁
for i in range(10):
    print(i)

# 业务逻辑中的变量应表达清楚
customer_shipping_address = get_shipping_address(customer_id)
```

一般建议：

- 作用域很小、含义明显的临时变量可以较短
- 跨函数、跨模块传递的数据应使用更完整的名称
- 不要为了追求短小而删除关键信息

### 5. 使用名词表示数据

变量通常代表数据，适合使用名词或名词短语：

```python
user = {"name": "Alice"}
product_price = 99.9
active_users = []
response_body = "OK"
```

表示行为的名称更适合函数：

```python
# 推荐：函数表示动作
calculate_total()
load_user()
send_email()
```

## 四、不同数据类型的命名方式

### 1. 字符串

根据字符串的实际含义命名，不要只使用 `str`：

```python
user_name = "Alice"
file_path = "/tmp/data.csv"
error_message = "Invalid input"
html_content = "<p>Hello</p>"
```

### 2. 数字

名称应体现数字的单位、用途或含义，尤其要明确时间、距离和金额的单位。

```python
user_count = 20
retry_count = 3
timeout_seconds = 30
file_size_bytes = 1024
price_cents = 999
```

不明确的命名容易造成误解：

```python
timeout = 30       # 不清楚单位是秒、毫秒还是分钟
price = 999         # 不清楚是元、分还是其他货币单位
```

### 3. 列表、元组和集合

多个对象组成的容器通常使用复数名词，或使用能体现集合性质的名称：

```python
users = []
product_names = ("Book", "Pen")
unique_tags = {"python", "backend"}
failed_requests = []
```

如果容器中的元素类型不明显，可以在名称中补充类型信息：

```python
user_ids = [101, 102, 103]
price_list = [10.5, 20.0]
name_to_user = {"alice": user}
```

单个对象使用单数，多个对象使用复数：

```python
user = users[0]
for user in users:
    print(user)
```

### 4. 字典

字典名称应体现“键到值”的映射关系：

```python
user_by_id = {101: "Alice", 102: "Bob"}
price_by_product_id = {1: 99.9, 2: 49.9}
name_to_age = {"Alice": 18, "Bob": 20}
```

常见结构可以使用以下命名模式：

- `*_by_*`：按照某个字段索引，例如 `user_by_id`
- `*_to_*`：表示键到值的映射，例如 `name_to_user`
- `*_mapping`：强调这是映射表，例如 `status_mapping`
- `*_lookup`：强调用于查询，例如 `country_lookup`

### 5. 布尔值

布尔变量最好以能表达真假含义的前缀开头：

- `is_`：表示是否处于某种状态
- `has_`：表示是否拥有某种内容
- `can_`：表示是否具备某种能力
- `should_`：表示是否应该执行某个动作
- `was_` / `will_`：表示过去或未来状态

```python
is_active = True
is_authenticated = False
has_permission = True
has_children = False
can_edit = True
should_retry = False
was_deleted = False
```

不推荐使用含义模糊的名称：

```python
active = True       # 可以使用，但 is_active 更明确
check = False       # 不清楚表示什么
flag = True         # 含义过于宽泛
```

条件判断应直接读起来像一句话：

```python
if is_authenticated and has_permission:
    update_profile()

if should_retry:
    retry_request()
```

### 6. 日期和时间

名称应明确表示是日期、时间点、时间间隔，必要时标明时区和单位：

```python
created_at = datetime.now()
updated_at = datetime.now()
start_date = date.today()
end_time = datetime.now()
duration_seconds = 60
request_timeout_ms = 5000
```

如果项目涉及多个时区，推荐在名称中明确时区含义：

```python
created_at_utc = datetime.now(timezone.utc)
local_start_time = get_local_time()
```

## 五、常量命名

常量是运行期间不应改变的配置值或固定值。Python 没有强制不可变的常量语法，通常通过全大写名称表达“请勿修改”。多个单词使用下划线分隔。

```python
MAX_RETRY_COUNT = 3
DEFAULT_PAGE_SIZE = 20
REQUEST_TIMEOUT_SECONDS = 30
API_BASE_URL = "https://api.example.com"

HTTP_OK = 200
STATUS_PENDING = "pending"
```

模块级常量通常定义在模块顶部：

```python
DEFAULT_LANGUAGE = "zh-CN"
SUPPORTED_FILE_EXTENSIONS = {".py", ".md", ".json"}


def create_config():
    return {
        "language": DEFAULT_LANGUAGE,
        "extensions": SUPPORTED_FILE_EXTENSIONS,
    }
```

以下名称不适合作为常量风格：

```python
maxRetryCount = 3       # 不符合 Python 常见约定
page_size = 20           # 如果是固定配置，应使用 DEFAULT_PAGE_SIZE
```

注意：全大写只是约定，不会阻止重新赋值：

```python
MAX_RETRY_COUNT = 3
MAX_RETRY_COUNT = 5      # Python 不会报错，但不应这样做
```

## 六、函数、方法、类和模块的命名

### 1. 函数和方法

函数与方法使用小写字母加下划线，名称通常由动词或动词短语组成：

```python
def calculate_total(items):
    ...


def get_user_by_id(user_id):
    ...


def validate_email_address(email):
    ...


def send_notification(message):
    ...
```

返回布尔值的函数也应体现判断含义：

```python
def is_valid_email(email):
    ...


def has_access(user, resource):
    ...


def can_delete(user, document):
    ...
```

方法名通常应体现对象上的动作：

```python
class ShoppingCart:
    def add_item(self, item):
        ...

    def remove_item(self, item_id):
        ...

    def calculate_total(self):
        ...
```

### 2. 类

类名使用 PascalCase，也称 CapWords：每个单词首字母大写，不使用下划线。

```python
class User:
    ...


class UserProfile:
    ...


class PaymentService:
    ...
```

类名通常使用名词，表示对象、概念或职责：

```python
class DatabaseConnection:
    ...


class EmailMessage:
    ...
```

不要把普通函数的命名风格用于类名：

```python
class user_profile:       # 不推荐
    ...


class userProfile:        # 不推荐
    ...
```

### 3. 异常类

异常类使用 PascalCase，并且通常以 `Error` 结尾：

```python
class ConfigurationError(Exception):
    pass


class InvalidTokenError(ValueError):
    pass


class DatabaseConnectionError(RuntimeError):
    pass
```

### 4. 模块和包

模块文件名使用小写字母，多个单词用下划线分隔，名称尽量简短：

```text
user_service.py
file_utils.py
http_client.py
```

包目录通常使用简短的小写名称，通常不使用下划线：

```text
utils/
models/
services/
```

避免使用容易与标准库或第三方库冲突的模块名：

```text
# 不推荐
json.py
random.py
logging.py
email.py

# 推荐
json_helpers.py
random_data.py
app_logging.py
email_service.py
```

### 5. 参数命名

函数参数使用与普通变量相同的 `snake_case` 风格。参数名应描述传入的数据：

```python
def create_user(user_name, email_address, is_active=True):
    ...
```

不要使用过于泛化的参数名：

```python
def process(data, value, obj):
    ...
```

如果函数确实处理通用数据，`data`、`value` 等名称可以使用，但应结合函数名称和类型注解提高可读性：

```python
def parse_json_data(raw_data: str) -> dict:
    ...
```

## 七、下划线的特殊含义

### 1. 单个前导下划线：`_name`

表示这是模块内部或类内部使用的名称，不属于公开 API。它主要是约定，并不会真正阻止访问。

```python
_internal_cache = {}


class UserService:
    def __init__(self):
        self._session = None
```

使用 `from module import *` 时，单个前导下划线开头的名称通常不会被导入。

### 2. 单个下划线：`_`

单个 `_` 常用于表示“这个值不会被使用”，或在交互式解释器中表示上一次表达式的结果。

```python
for _ in range(3):
    print("run")

first, _, last = ("A", "B", "C")
```

在国际化项目中，`_` 也经常被用作翻译函数的别名，但应遵循项目既有约定。

### 3. 两个前导下划线：`__name`

在类中，两个前导下划线会触发名称改写（name mangling），用于降低子类意外覆盖属性的可能性。

```python
class Account:
    def __init__(self):
        self.__balance = 0
```

它不是严格意义上的私有属性，也不应作为日常封装的默认方式。一般业务代码优先使用单个前导下划线表示内部成员。

### 4. 两端两个下划线：`__name__`

两端两个下划线的名称通常是 Python 预留的特殊名称，也叫 dunder 名称。不要为普通业务变量随意创建这类名称。

```python
class User:
    def __init__(self, name):
        self.name = name

    def __str__(self):
        return self.name
```

常见特殊方法包括：

```python
__init__       # 初始化对象
__str__        # 返回可读字符串
__repr__       # 返回调试表示
__len__        # 支持 len(object)
__iter__       # 支持迭代
__enter__      # 进入上下文管理器
__exit__       # 退出上下文管理器
```

### 5. 末尾单个下划线：`name_`

当理想名称与关键字冲突时，可以在末尾增加一个下划线：

```python
class_ = "User"
from_ = "database"
```

这比使用难以理解的缩写更清晰。

## 八、命名中的常见约定

### 1. 单数与复数

- 单个对象使用单数：`user`、`product`、`file`
- 多个对象使用复数：`users`、`products`、`files`
- 映射关系使用 `*_by_*` 或 `*_to_*`：`user_by_id`、`id_to_user`

```python
user = get_user()
users = get_users()
user_by_id = {user.id: user}
```

### 2. 成对概念保持一致

同一项目中，应使用稳定、对称的词汇：

```python
start_time / end_time
min_value / max_value
first_name / last_name
source_path / target_path
request_data / response_data
```

不要在不同位置混用同义词，除非它们确实代表不同概念：

```python
# 不推荐：同一概念使用多个词
user_name = "Alice"
customer_name = "Bob"
client_name = "Carol"
```

### 3. 避免否定式布尔变量

双重否定会让条件难以理解：

```python
is_not_disabled = True       # 阅读成本较高

# 更推荐
is_enabled = True
```

如果业务本身就是否定状态，可以直接使用清晰的名称：

```python
is_deleted = False
is_invalid = False
has_error = False
```

### 4. 在名称中体现单位

数字单位应尽量写入变量名，避免调用方误用：

```python
cache_ttl_seconds = 300
max_file_size_mb = 10
retry_delay_ms = 500
user_distance_km = 2.5
```

### 5. 类型注解不能代替命名

类型注解可以补充信息，但不能弥补含义不清的名称：

```python
# 类型明确，但业务含义仍不清楚
x: int = 10

# 名称和类型都清晰
max_retry_count: int = 10
```

推荐同时使用清晰命名和类型注解：

```python
user_ids: list[int] = [101, 102]
user_by_id: dict[int, str] = {101: "Alice"}
is_ready: bool = True
```

## 九、循环变量和临时变量

### 1. 简单循环可以使用短名称

在很小的循环作用域中，`i`、`j`、`k` 可以表示索引，但复杂逻辑中应使用有意义的名称。

```python
for i in range(10):
    print(i)

for user in users:
    print(user.name)
```

二维数据中可以使用 `row`、`column`，比单纯使用 `i`、`j` 更清楚：

```python
for row in matrix:
    for value in row:
        print(value)
```

### 2. 不要滥用 `temp`、`foo`、`bar`

临时变量可以短暂存在，但如果逻辑稍微复杂，就应使用准确名称：

```python
# 简单交换可以接受
first, second = second, first

# 复杂处理中应说明含义
normalized_email = normalize_email(raw_email)
```

### 3. 推导式中的变量要保持可读

```python
active_user_names = [
    user.name
    for user in users
    if user.is_active
]
```

不要把推导式写成难以理解的单字母组合：

```python
x = [u.n for u in us if u.a]  # 不推荐
```

## 十、容易出现的问题

### 1. 使用大小写内置名称

`list`、`dict`、`str`、`id`、`input`、`type`、`format`、`open`、`sum` 等名称最好不要作为变量名。

### 2. 使用过于宽泛的名称

以下名称往往缺乏上下文：

```python
data = ...
info = ...
result = ...
thing = ...
value = ...
obj = ...
```

它们不是绝对错误。在函数作用域很小或数据确实通用时可以使用，但跨模块、跨函数使用时应进一步具体化：

```python
user_data = ...
order_summary = ...
api_response = ...
configuration = ...
```

### 3. 名称与实际类型不一致

```python
users = "Alice"       # 名称像列表，实际是字符串
user_list = {1, 2, 3}  # 名称像列表，实际是集合
```

应让名称与实际数据结构保持一致：

```python
user_name = "Alice"
user_ids = {1, 2, 3}
```

### 4. 只通过数字区分变量

```python
user1 = ...
user2 = ...
user3 = ...
```

如果每个变量有不同角色，应使用角色名称：

```python
admin_user = ...
regular_user = ...
guest_user = ...
```

### 5. 变量名与作用域不匹配

名称越容易在更大范围被看到，就越需要完整、准确：

```python
# 很小的局部作用域中可以接受
for item in items:
    process(item)

# 模块级或跨函数共享时应更加具体
DEFAULT_DATABASE_CONNECTION_TIMEOUT_SECONDS = 30
```

## 十一、推荐示例

下面是一个综合示例：

```python
MAX_LOGIN_ATTEMPTS = 5
DEFAULT_PAGE_SIZE = 20


class UserRepository:
    def __init__(self, database_url: str):
        self._database_url = database_url

    def get_active_users(self, page_number: int = 1) -> list[dict]:
        offset = (page_number - 1) * DEFAULT_PAGE_SIZE
        users = self._query_users(
            offset=offset,
            limit=DEFAULT_PAGE_SIZE,
        )
        return [user for user in users if user["is_active"]]

    def _query_users(self, offset: int, limit: int) -> list[dict]:
        return []


def can_login(login_attempt_count: int) -> bool:
    return login_attempt_count < MAX_LOGIN_ATTEMPTS
```

这个示例体现了以下约定：

- 常量使用 `UPPER_SNAKE_CASE`
- 类使用 `PascalCase`
- 方法、函数和参数使用 `snake_case`
- 内部成员使用单个前导下划线
- 布尔字段使用 `is_` 前缀
- 容器使用复数名称
- 数字名称表达了具体用途
- 类型注解补充了变量和函数的类型信息

## 十二、命名检查清单

提交代码前，可以快速检查：

- [ ] 名称只包含字母、数字和下划线，且没有以数字开头
- [ ] 没有使用 Python 关键字
- [ ] 没有覆盖 `list`、`str`、`id`、`sum` 等内置名称
- [ ] 普通变量、参数、函数和方法使用 `snake_case`
- [ ] 类和异常使用 `PascalCase`
- [ ] 常量使用 `UPPER_SNAKE_CASE`
- [ ] 布尔值使用 `is_`、`has_`、`can_` 或 `should_` 等前缀
- [ ] 列表、集合等多元素容器通常使用复数名词
- [ ] 数字名称包含必要的单位，例如 `_seconds`、`_ms`、`_bytes`
- [ ] 名称准确反映实际数据类型和业务含义
- [ ] 没有不必要的缩写、否定和单字母变量
- [ ] 模块名没有与标准库或第三方库重名
- [ ] 没有滥用双下划线或自定义 dunder 名称
- [ ] 同一概念在整个项目中使用统一词汇

## 十三、核心原则

Python 命名可以概括为：

> **合法、清晰、一致、可读，并且让名称与数据的真实含义保持一致。**

当“名称更短”和“含义更清楚”发生冲突时，优先选择含义更清楚的名称；当团队已有命名规范时，优先遵循项目规范。命名的最终目标不是追求形式统一，而是降低理解、维护和修改代码的成本。
